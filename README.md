# MediaShelf

Android-приложение для просмотра и персональной организации каталога персонажей Rick and Morty. Проект построен по принципу **offline-first**: интерфейс использует локальные данные Room, а сеть необходима для их первоначальной загрузки и последующего обновления.

## Функциональность

- Каталог персонажей из Rick and Morty API и экран подробной информации.
- История просмотров (recent).
- Личные статусы персонажей, оценки, заметки, закрепление и скрытие элементов.
- Пользовательские коллекции с отдельной связью между коллекциями и персонажами (`collection_members`).
- Фильтрация каталога по пользовательским данным.
- Настройки отображения, темы и фоновой предзагрузки.
- Работа с ранее загруженным каталогом без подключения к интернету.

## Архитектура и хранение данных

- **Jetpack Compose и Navigation Compose** — отдельные экраны и навигация с back stack.
- **ViewModel, Coroutines и Flow** — состояние экрана и реактивные данные.
- **Hilt** — внедрение зависимостей: `@HiltViewModel`, `@Inject`, модули `DatabaseModule` и `NetworkModule`; зависимости не создаются непосредственно внутри ViewModel.
- **Room** — кэш персонажей, пользовательские записи, коллекции и история; локальная база является источником данных для UI.
- **DataStore Preferences** — настройки приложения, не пользовательские списки или заметки.
- **Retrofit и kotlinx.serialization** — загрузка данных из внешнего API.
- **WorkManager** — фоновое обновление каталога с учётом сетевых условий и повторных попыток при ошибках.

Свежесть страниц кэша отслеживается в отдельной таблице `cached_pages`. Для неё предусмотрена миграция Room с версии 1 на версию 2 без очистки пользовательских данных. TTL составляет **24 часа**. Если локальные записи уже существуют, приложение может отображать их без сети. Новые данные из API обновляют локальное хранилище.

## Новые пользовательские сценарии

1. **Персональная организация каталога:** пользователь меняет личные статусы, оценки, закрепление и скрытие персонажей; данные хранятся в Room и используются при фильтрации.
2. **Собственные коллекции:** пользователь создаёт коллекции и редактирует и удаляет коллекции с подтверждением, управляет привязкой персонажей к ним; для связи используется отдельная таблица.
3. **История и заметки:** приложение сохраняет пользовательскую историю и заметки, доступные после перезапуска и без интернета.
4. **Офлайн-доступ и обновление:** ранее загруженный каталог доступен из Room; актуализация выполняется отдельно через сеть и WorkManager.

## Тестирование

Локальные unit-тесты находятся в `app/src/test/` и проверяют правила коллекций, фильтрации, TTL, планирования синхронизации, продолжение загрузки страниц после ошибок и логику ViewModel.

Инструментальные тесты находятся в `app/src/androidTest/` и проверяют взаимодействие с Room и выбор фильтра личного статуса в Compose UI.

Из корня проекта в PowerShell:

```powershell
.\gradlew.bat testDebugUnitTest
```

Для инструментальных тестов нужен запущенный Android-эмулятор или подключённое Android-устройство:

```powershell
.\gradlew.bat connectedDebugAndroidTest
```

## Запуск

1. Открой корневую папку проекта `FINALWORK1` в Android Studio.
2. Дождись Gradle Sync; при необходимости установи требуемый Android SDK.
3. Выбери устройство и запусти конфигурацию `app`.
4. Для первоначального получения данных каталога нужен интернет. После загрузки ранее сохранённые данные доступны из Room в офлайн-режиме.

Локальные файлы `local.properties`, каталоги сборки и настройки IDE не включаются в Git благодаря `.gitignore`.
